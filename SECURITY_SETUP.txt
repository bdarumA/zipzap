SIANKAI V5 — Traffic Security

Behavior:
- Same sales page content for all visitors, including Meta review crawlers.
- All outbound LINE clicks go through /api/traffic-check.
- Optional Cloudflare Turnstile; when configured, a challenge appears before LINE is opened.
- If Turnstile is not configured, the server records an accepted outbound check without verifying that the visitor is human.
- Best-effort 7-day outbound click statistics in Admin; KV is eventually consistent and concurrent updates can lose increments.
- No visitor identities, IP addresses or user agents are stored by this implementation.

CONFIGURE OPTIONAL TURNSTILE:
1. Create a Cloudflare Turnstile widget for your published hostnames.
2. In the Cloudflare Pages Production environment add:
   SIANKAI_TURNSTILE_SITE_KEY  (Text; public widget site key)
   SIANKAI_TURNSTILE_SECRET    (Secret; private secret)
3. Redeploy once to activate environment variables.
4. Verify the challenge on an actual phone and desktop.
5. The site content stays identical for humans and crawlers; only the same LINE-click verification flow applies to everyone.

CAVEATS:
- Turnstile is not a perfect way to distinguish human/bot; some automation may pass.
- Facebook Ads approval is separate and is not guaranteed.
- This is not a cloaking system or a method for avoiding ad review.
- Existing Cloudflare KV binding SIANKAI_SETTINGS and SIANKAI_ADMIN_TOKEN are still required.
- Check local privacy notice, consent and Meta policies before running the Pixel.

V7 NOTE:
- V7 validates Turnstile token server-side, including the expected hostname and
  action = line_click. Register every actual production hostname in Turnstile.
- V7 traffic analytics use new D1 binding SIANKAI_TRAFFIC_DB; no KV event counter
  writes per visit/click anymore.
- Server-side page counting includes bots that do not execute JavaScript,
  but identified automation signals can still be spoofed or unavailable.
- You MUST NOT interpret zero "Verified automation" as zero Meta bots.
